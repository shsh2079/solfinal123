==========================================================
 Gemini AI Advisor — 추천 결과 조회 가이드
==========================================================

[이 가이드가 하는 일]
EKS 메트릭을 10분마다 자동 수집해 Gemini AI가 오토스케일링을
추천하고, 그 결과를 확인하는 방법을 안내합니다.

[추천 결과 저장 위치]
  1. GCP Cloud Logging  → 이력 영구 보관 (브라우저)
  2. 로컬 파일          → scripts/data/recommendation-*.json
  3. EKS CronJob 로그   → kubectl logs
  4. 터미널 즉시 출력   → 수동 실행


==========================================================
 1. GCP Cloud Logging (브라우저) — 이력 전체 조회
==========================================================

접속: https://console.cloud.google.com/logs/query  
프로젝트: soldesk-gcp

──────────────────────────────────────────────────────────
[1-A] Gemini 추천 결과 조회
──────────────────────────────────────────────────────────
    logName="projects/soldesk-gcp/logs/gemini-recommendations"

    # 우선순위 높은 것만
    logName="projects/soldesk-gcp/logs/gemini-recommendations"
    jsonPayload.priority="now"


──────────────────────────────────────────────────────────
[1-B] 원본 메트릭 로그 조회
──────────────────────────────────────────────────────────
    logName="projects/soldesk-gcp/logs/eks-metrics"


──────────────────────────────────────────────────────────
[1-C] CLI로 최근 로그 확인
──────────────────────────────────────────────────────────
    gcloud logging read \
      'logName="projects/soldesk-gcp/logs/gemini-recommendations"' \
      --project=soldesk-gcp \
      --limit=3 \
      --format="json"


==========================================================
 2. EKS CronJob 실행 상태 확인
==========================================================

──────────────────────────────────────────────────────────
[2-A] CronJob 상태
──────────────────────────────────────────────────────────
    kubectl get cronjob ai-advisor -n ticketing


──────────────────────────────────────────────────────────
[2-B] 최근 Job 결과
──────────────────────────────────────────────────────────
    kubectl get jobs -n ticketing | grep ai-advisor | tail -3


──────────────────────────────────────────────────────────
[2-C] CronJob 로그 확인
──────────────────────────────────────────────────────────
    kubectl logs -n ticketing -l job-name=ai-advisor -f

    ==========================================================
 7. 세분화 메트릭 모니터링 (실시간 관측)
==========================================================

[설명]
현재 클러스터 상태(SQS, HPA, KEDA, 노드 등)를
15초 단위로 실시간 확인하는 CLI 모니터링 도구입니다.
(추천 기능 ❌ / 상태 관측 + 단기 예측 ⭕)


──────────────────────────────────────────────────────────
[7-A] 환경 변수 로드
──────────────────────────────────────────────────────────
    source .env.local


──────────────────────────────────────────────────────────
[7-B] CLI 반복 출력 (실시간 모니터링)
──────────────────────────────────────────────────────────
    # 15초 간격으로 지속 출력
    python3 scripts/realtime_monitor.py


──────────────────────────────────────────────────────────
[7-C] 1회 실행 (스냅샷 확인)
──────────────────────────────────────────────────────────
    # 현재 상태만 출력 후 종료
    python3 scripts/realtime_monitor.py --once


──────────────────────────────────────────────────────────
[7-D] 파일 저장 (이력 관리)
──────────────────────────────────────────────────────────
    # 반복 실행 + 파일 저장
    python3 scripts/realtime_monitor.py --file

    # 저장 위치
    # 최신: scripts/data/monitor-latest.txt
    # 이력: scripts/data/monitor-YYYYMMDD-HHMMSS.txt


──────────────────────────────────────────────────────────
[7-E] 자동 스케일링 보조 (예측 기반)
──────────────────────────────────────────────────────────
    # 증가 속도 기반으로 maxReplicas 선제 조정
    python3 scripts/realtime_monitor.py --auto


──────────────────────────────────────────────────────────
[7-F] 출력 예시 (구조)
──────────────────────────────────────────────────────────
    [현재 상태]
    SQS backlog: 800
    RDS conn   : 120

    [KEDA - worker-svc]
    queueLength      : 800
    current replicas: 4
    desired replicas: 6

    [HPA - read api]
    cpu    : 62%
    current: 3
    desired: 5
    max    : 23

    [예측]
    SQS 증가 속도: +50.0 msg/sec
    SQS 임계까지: 22.8 sec


──────────────────────────────────────────────────────────
[7-G] 해석 가이드
──────────────────────────────────────────────────────────
    # backlog ↑ + 처리속도 ↓ → 병목 발생
    # desired > current → 스케일 업 진행 중
    # CPU 70%↑ → HPA 확장 임박
    # "임계까지 XX초" → 사전 대응 필요

    # 즉시 대응: HPA / KEDA (자동)
    # 사전 대응: --auto (선제 조정)
    # 전략 개선: Gemini 추천 (10분 단위)
